# 管理员修改用户分组时清空 Token 分组

## 目标

当管理员通过用户管理修改用户所属分组时，如果分组确实发生变化，则将该用户所有 Token 的 `group` 统一设置为空字符串，使这些 Token 后续继承用户的新分组。

## 方案

- 在用户更新流程中比较修改前后的用户分组；未变化时不触碰 Token。
- 用户记录与该用户 Token 的分组更新使用同一个 GORM 事务，避免只更新一部分。
- 只更新 Token 的 `group` 字段，不影响 key、额度、状态、过期时间、模型限制等字段。
- 事务提交后清理该用户全部 Token 的 Redis 缓存，确保 TokenAuth 不继续使用旧分组；用户缓存仍按现有用户更新流程刷新。
- 使用 GORM 的批量 `Update`，保持 SQLite、MySQL、PostgreSQL 兼容。

## 错误处理与兼容性

- 任一数据库更新失败均回滚事务并返回错误。
- Redis 缓存清理失败只记录日志，不回滚已经提交的数据库事务。
- 如果用户没有 Token，批量更新视为成功。

## 测试

- 用户分组变化时，所有该用户 Token 的 `group` 变为空，其他用户 Token 不变。
- 用户分组未变化时，不清空 Token 分组。
- Token 更新失败时，用户分组更新回滚。
