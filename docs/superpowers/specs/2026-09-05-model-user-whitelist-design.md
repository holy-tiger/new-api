# 按模型配置用户白名单设计

## 背景与目标

为模型元数据增加用户 ID 白名单，用于限制某个模型只能被指定用户访问，不需要为该模型单独创建渠道。白名单为空或未配置时保持现有访问逻辑；白名单非空时，仅名单内用户可以调用该模型。

无权限请求必须在渠道选择前被拒绝，返回 HTTP 403 和 `model_access_denied`，不得进入渠道选择、上游请求或扣费流程。无权限用户也不应在模型列表或 Playground 中看到该模型。

Root 用户默认绕过白名单；普通管理员不绕过，必须出现在白名单中。现有 Token 分组、Token 模型限制和渠道 Ability 继续生效，白名单作为额外的用户级限制。

## 方案选择

采用在现有 `models` 表中增加 JSON/TEXT 字段的方案，而不是新增模型-用户关联表或全局配置项。

原因：

- 白名单属于模型元数据，和现有模型编辑、匹配规则及 CRUD 生命周期一致。
- 典型名单规模较小，TEXT JSON 足以满足存储需求。
- 使用 `type:text` 配合 GORM JSON serializer，兼容 SQLite、MySQL 和 PostgreSQL。
- 不需要创建额外渠道，也不需要为规则模型预展开关联记录。

## 数据模型与管理端

`model.Model` 增加用户白名单字段，数据库列使用 TEXT 存储 JSON 数组，API JSON 表现为整数数组。空数组或空值均表示不限制访问。保存时需要去重并忽略非法/非正数 ID；读取时返回规范化后的整数数组。

现有后台“模型管理 → 编辑模型”表单增加用户 ID 白名单输入控件，支持输入多个整数 ID，并在提交时发送整数数组。创建、编辑、详情和列表接口均保留该字段；后台模型配置列表不按当前登录用户过滤，以保证管理员可以维护受限模型。

模型表继续由现有 `AutoMigrate` 迁移，不新增数据库特定 SQL。

## 访问判断

新增统一的模型访问判断 helper，输入请求模型名、用户 ID 和角色，并返回是否允许访问。匹配规则与现有模型元数据一致，优先级为：

1. 精确名称；
2. 前缀名称；
3. 后缀名称；
4. 包含名称。

当匹配到的模型配置没有白名单时放行；没有匹配到模型配置时也放行。匹配到非空白名单时，仅当用户 ID 在名单中才放行。Root 角色直接放行；普通管理员不享受绕过权限，必须在名单中。

访问判断使用请求中的可见模型名，并在 compact 等内部模型后缀场景使用规范化名称，避免通过后缀变体或规则模型匹配绕过限制。渠道模型映射属于后续上游转换步骤，不能替代前置的可见模型权限判断。

在 `middleware.Distribute()` 中完成模型解析后、渠道亲和性和渠道选择之前调用 helper；指定渠道路径也必须执行该校验。拒绝时调用统一 OpenAI 错误响应，状态码 403，错误码 `model_access_denied`，并立即终止 Gin 链路。

## 模型列表过滤

抽出按用户过滤模型名的统一函数，并应用到以下用户可见列表：

- OpenAI、Anthropic、Gemini 的 `/v1/models`、`/v1beta/models` 等接口；
- Dashboard 的 `/api/models`；
- `/api/user/self/models`；
- Playground 使用的模型来源。

过滤在现有 Token 模型限制、用户分组/自动分组和计费配置筛选之后执行，避免改变现有权限语义。Root 用户跳过白名单过滤；普通管理员与普通用户按名单过滤。过滤后列表为空时保持各接口现有的空列表响应格式，不引入额外错误。

## 用户角色上下文

用户缓存结构和 Gin 上下文增加角色字段，使 Token 请求可以在不额外查询用户表的情况下判断 Root。现有缓存缺失角色时沿用数据库回源并刷新缓存；角色变更沿用现有用户缓存失效机制。

## 错误处理与兼容性

- 新增 `types.ErrorCodeModelAccessDenied = "model_access_denied"`。
- 新增中英文 distributor 文案，错误类型保持 `new_api_error`。
- 白名单字段读取或解析失败时记录错误，并按安全策略将该模型视为受限模型：非 Root 用户拒绝访问且从用户模型列表隐藏；正常保存路径必须拒绝无法解析的输入，避免写入不可解释的配置。
- 旧模型记录没有该列或列为空时视为空白名单，行为与升级前一致。
- 所有 JSON 编解码使用 `common.Marshal`/`common.Unmarshal` 等项目封装，不在新业务逻辑中直接调用 `encoding/json` 的编解码函数。

## 测试计划

后端测试覆盖：

- 空白名单和未配置字段保持放行；
- 普通用户不在名单时返回 403 和 `model_access_denied`；
- 名单用户可以调用；
- Root 绕过；普通管理员不绕过；
- 精确、前缀、后缀、包含规则均按预期匹配；
- compact/名称后缀变体不能绕过；
- 白名单拒绝发生在渠道选择前，既不选渠道也不进入后续 relay；
- Token 分组、Token 模型限制和 Ability 仍独立生效；
- `/v1/models`、Dashboard、用户模型列表和 Playground 来源均过滤无权限模型；
- SQLite 自动迁移和 JSON 字段读写可用。

前端验证模型编辑表单的数组输入、回填、去重和空值提交，并运行现有 i18n lint、Go 测试及前端构建/相关测试。
